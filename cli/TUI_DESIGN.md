Final visual rules
1. FULL-WIDTH CONVERSATION
   No permanent left sidebar.


2. LARGE BOTTOM COMPOSER
   The composer is the primary input.


3. NO DUPLICATE INPUT
   Never show:
       hermes> Type a task or /command…


   on the landing screen.


4. MODEL INFO IS INSIDE THE COMPOSER
   Build · DeepSeek V4 Flash Free · OpenCode Zen · max


5. CONVERSATION USES SECTIONS
   Thought
   Questions
   Tool calls
   Terminal output
   Findings
   Final response


6. BOTTOM STATUS
   Project path
   Usage / context
   / to commands


7. VISUAL STYLE
   Black background
   Off-white text
   Cyan / blue accents
   Orange for Thought / attention
   Gray panels
   Thin separators
   Minimal borders

This is the final direction I would use for the TUI: much closer to the screenshot you provided than the earlier sidebar-based design, while retaining Hermes-specific elements such as experiments, skills, approvals, findings, and the backend status.
