PART D - HERMES AGENT BRIDGE (connect to the Nous Research Hermes Agent)
--------------------------------------------------------------------------

[x] Bridge mode: hand experiments to a locally-running Hermes Agent
    - Concept: the app PREPS (project scan, relevant files, memory) then
      hands the task to the user's local Hermes Agent (Nous Research,
      hermes-agent.nousresearch.com) which EXECUTES with its own tools
      (terminal, file edits, git, skills, memory) — then the app verifies
      and reports. The app is the work-prep layer; the agent is the doer.
    - Config: backend/data/bridge.json + Settings view "Hermes Agent
      bridge" card. Fields: enabled, baseUrl (default
      http://127.0.0.1:8642/v1 — the agent's OpenAI-compatible API
      server), apiKey (API_SERVER_KEY), verifyCommand (optional, e.g.
      "npm test"), timeoutMs (default 5 min). Test connection button.
    - Agent setup (one time, on the user's machine): install Hermes Agent
      (irm https://hermes-agent.nousresearch.com/install.ps1 | iex), set
      API_SERVER_ENABLED=true + API_SERVER_KEY in ~/.hermes/.env, run
      `hermes gateway`, then point the app at it. The agent needs its own
      model key (Nous Portal / OpenRouter / Groq / any).
    - Handoff flow (backend/server.js -> backend/bridge.js):
      1. buildProjectContext + memory as usual (existing code)
      2. snapshot the project (sizes + mtimes, ignoring node_modules etc.)
      3. build handoff prompt: task + project path/map + relevant files +
         memory (+ last messages on replies) with a strict
         Steps/Findings/Summary output structure
      4. POST {baseUrl}/chat/completions (Bearer apiKey, 5 min timeout)
      5. agent's final answer is stored on the experiment; progress shows
         "Handing off to Hermes Agent" while it works
      6. re-snapshot -> diff -> changed/added/removed files reported on a
         "Handed off to Hermes Agent" card in the experiment view
      7. verifyCommand runs in the project folder (skipped at trust
         level 1 — suggest only; exit code + output shown on the card)
    - Behavior notes:
      - Bridge only engages when a project is attached and bridge is on;
        otherwise the built-in AI flow runs unchanged. UI/image/brainstorm
        tasks stay local on purpose (bridge is for doing work on code).
      - If the agent is unreachable the experiment fails with a clear
        message ("Cannot reach the Hermes Agent at ... — start it with
        \`hermes gateway\`"), no silent fallback.
      - No live streaming: the UI shows "waiting for the agent" until the
        final answer lands (agent streams internally, we take the final
        message). Streaming integration is a future nicety.
      - Experiment cards get an "agent" badge; replies in a bridged
        experiment also go through the bridge with conversation history.
    - Tests: backend/test/bridge.test.js (12 tests, node:test, mocked
      fetch): config defaults/clamping/round-trip, callAgentApi success /
      auth header / unreachable / non-ok / empty response, testBridge ping,
      handoff prompt contents, snapshot diff detects changed/added/removed
      and ignores node_modules. All pass (npm test).
